# upcloud-dev-box — NixOS box on UpCloud, deployed from git

One server in **San Jose** (default plan `STARTER-4xCPU-8GB`, ~USD 26/mo) plus a persistent 20 GB storage
at `/data`. The OS is **NixOS, declared in `hosts/dev-box/` at the repo root**.

| Layer | Owned by | Change it by |
|---|---|---|
| Server, storage, keys | `stacks/upcloud-dev-box/*.tf` | PR → merge → `deploy.yml` runs `tofu apply` |
| The OS: users, packages, tmux, docker, services | `hosts/dev-box/*.nix` | PR → merge → **comin on the box** pulls main and switches (~1 min) |

Lifecycle: `tofu apply` boots an Ubuntu template → cloud-init labels `/data` → the
same apply runs **nixos-anywhere** from the CI runner, which kexecs into a NixOS
installer, partitions `/dev/vda` per `hosts/dev-box/disko.nix`, installs the flake,
reboots. ~5 min. From then on comin polls `main` every 60 s.

The server is cattle; `/data` is the pet (daily backups, 7 kept, `prevent_destroy`).

## What you need

| Credential | Where | Used for |
|---|---|---|
| `UPCLOUD_TOKEN` | `secrets/terraform.env` (SOPS) | everything the provider does |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | `secrets/terraform.env` (SOPS) | S3 state only |
| GitHub public keys | `hosts/dev-box/configuration.nix` (`sshKeys`) + `ssh.tf` | SSH as `dev` / `root` |

A CI bootstrap SSH key is generated by Terraform (state only) so the deploy job can
reach the fresh template. On the box, after first SSH: `claude` login and
`gh auth login --with-token` with a fine-grained PAT. Nothing else.

## Before the first apply (one-time, Mike)

1. Create an API token in the UpCloud Hub with full access (or a sub-account with
   server + storage permissions). Add it: `sops secrets/terraform.env` → append
   `UPCLOUD_TOKEN=...` → save → commit.
2. Confirm plan and zone names (both are rejected by the API if wrong):
   ```bash
   sops exec-env secrets/terraform.env 'curl -s -H "Authorization: Bearer $UPCLOUD_TOKEN" https://api.upcloud.com/1.3/plan' | jq '.plans.plan[] | select(.core_number==4 and .memory_amount==8192) | {name, storage_size}'
   sops exec-env secrets/terraform.env 'curl -s -H "Authorization: Bearer $UPCLOUD_TOKEN" https://api.upcloud.com/1.3/zone' | jq '.zones.zone[] | select(.id|startswith("us")) | .id'
   ```
   Adjust `var.plan` / `var.zone` defaults if needed.
3. Merge. Watch the deploy job: it prints the cloud-init log, then nixos-anywhere's
   progress, then the outputs (`ssh_command`).

## Reaching it

### Private LifeData search (prepared 2026-10-07)

`hosts/dev-box/personal-search.nix` declares an independent read-only browser/API
service. It listens on loopback port 8765; it does not start the orchestrator.
The condition skips startup until its code checkout exists. Nix supplies Python
and PyYAML; there is no dependency on a temporary cloud-workspace virtualenv.

| Data | Durable location |
|---|---|
| Curated/searchable notes | `/data/lifedata/brain` (dedicated read mirror of private `pix0r/brain`; authored changes go through existing Git/Obsidian workflows) |
| Future private original exports | `/data/lifedata/archive` (outside Git and currently **not ingested**; inaccessible to search service) |
| Rebuildable private index | `/data/lifedata/index/search.sqlite` |
| Service config | This repository's NixOS module |

After reviewing/landing brain PR #11 and this infra change, perform setup from an
authorized laptop/server session. This managed Codex workspace currently has no
server credentials, VPN or permitted outbound TCP route; preparing these files
does not deploy the dataset or prove the server is healthy.

As `dev`, check `findmnt /data`, `tailscale status`, and GitHub read access before
setup. Confirm the `/data` backup job and test restoration separately; provider
volume backups do not prove application recovery or a desired encryption policy.
If an existing `/data/lifedata/brain` checkout exists, inspect its branch and
working tree instead of overwriting it.

```bash
mkdir -p /data/lifedata
git clone https://github.com/pix0r/brain.git /data/lifedata/brain
sudo systemctl start personal-search
systemctl status personal-search --no-pager
curl --fail http://127.0.0.1:8765/api/status
sudo tailscale serve status
```

The clone command above assumes brain PR #11 has landed on main and the host's
existing GitHub authorization works. To validate the draft first, explicitly clone
`--branch claude/life-os-recovery-2026-10-07`; switch this dedicated mirror to main
after merge. Do not switch the existing agent working checkout to deploy search.

If HTTPS port 8443 is unused in `tailscale serve status`, enable a private URL
without replacing an existing port-443 app:

```bash
sudo tailscale serve --bg --https=8443 http://127.0.0.1:8765
```

Open the **actual URL printed by that command**, from a laptop/phone signed into
the permitted tailnet. This uses Serve, not public Funnel. Restrict access with
tailnet grants/ACLs if the tailnet includes other users/devices. The service accepts
the server's exact Tailscale DNS name on port 8443; restart it after Tailscale first
connects or the DNS name changes. `tailscale serve` state already persists through
the existing `/data/tailscale` bind mount. This setup has not been remotely run.

For laptop-only temporary access before Serve is configured, use
`ssh -N -L 8765:127.0.0.1:8765 dev@<verified-server-address>` and open
`http://127.0.0.1:8765` **on that laptop**. SSH target/identity must come from the
existing infrastructure outputs or tailnet, not a stale note's IP.

Updates are explicit initially: in the dedicated clean mirror, `git pull --ff-only`,
then `sudo systemctl restart personal-search`. Restart rebuilds the index atomically.
The browser exposes counts/index date and labels source freshness as unverified.
There is no automatic source fetch or ChatGPT ingestion. If rebuilding fails,
the prior index survives, but service startup fails visibly; inspect the service
journal before retrying. Export deletion propagates when the index is rebuilt.

- Public name: **`dev-box.matz.io`** (Route 53 A record, TTL 60, follows the IP through
  replacements). `ssh dev@dev-box.matz.io`. Add to `~/.ssh/config` on the laptop:
  `Host dev` / `HostName dev-box.matz.io` / `User dev`.
- Tailnet (once `hosts/dev-box` has Tailscale): `ssh dev@dev-box`, and the orchestrator
  UI at `http://dev-box:4000` from any tailnet device, no SSH tunnel.

## Day to day

- **Change the box:** edit `hosts/dev-box/configuration.nix`, PR (CI evaluates the
  flake), merge. `journalctl -u comin -f` on the box shows the switch.
- **Add an Elixir app:** release under `/data/apps/<name>`, adapt the
  `systemd.services` pattern in `configuration.nix`.
- **Bump nixpkgs:** `nix flake update` (Docker recipe below), commit `flake.lock`.
- **Turn off:** PR with `enabled = false`, merge. Storage stays. **On:** flip back;
  new server, fresh install, same `/data`, same home dir.
- **Reinstall from scratch:** `tofu apply -replace='upcloud_server.dev_box[0]'` (from CI:
  push a no-op change to `cloud-init/` — any change there replaces the server).

## Working without installing nix or tofu on the laptop

```bash
# validate the flake (repo root; from a git worktree copy flake.nix + hosts/ to a
# scratch dir first — the worktree's .git pointer is not visible inside the container)
docker run --rm -v "$PWD":/w -w /w nixos/nix:latest \
  nix --extra-experimental-features "nix-command flakes" \
  eval --raw .#nixosConfigurations.dev-box.config.system.build.toplevel.drvPath

# plan this stack (apply needs nix for the install step → do it in CI)
cd stacks/upcloud-dev-box
tofu() { docker run --rm -it -v "$PWD":/work -w /work \
  -e UPCLOUD_TOKEN -e AWS_ACCESS_KEY_ID -e AWS_SECRET_ACCESS_KEY -e AWS_REGION=us-east-1 \
  ghcr.io/opentofu/opentofu:1.9.0 "$@"; }
sops exec-env ../../secrets/terraform.env 'tofu plan'
```

## Gotchas

- **UpCloud's firewall is stateless for UDP.** Inbound rules must accept UDP replies
  (source port 53 for DNS, 123 for NTP) or name resolution silently dies while TCP
  keeps working. Symptom: `Resolving timed out`, comin cannot pull, Claude Code cannot
  reach the API. `firewall.tf` carries those rules; do not remove them.

- `hosts/dev-box/disko.nix` owns `/dev/vda` only. `/data` is never declared to disko,
  so reinstalls cannot format it. cloud-init formats it **only if blank**.
- UpCloud firewall is on (trial accounts cannot disable it) with accept rules for 22 +
  mosh and no catch-all drop, so it can never lock you out; the NixOS firewall is the
  one that actually drops everything else. Add a final drop rule for defence in depth
  once the account is out of trial and you have tested it.
- If nixos-anywhere fails mid-way the server is left in the kexec installer; re-run
  the apply with `-replace='upcloud_server.dev_box[0]'`.
- `system.stateVersion` stays `26.05` forever; bumping nixpkgs is `flake.lock`.
- The Hetzner `stacks/dev-box` remains (off, `enabled=false`) until you delete it.
